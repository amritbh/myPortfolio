# Cognito Authentication Flow

This project uses **AWS Cognito** for user authentication with Google OAuth federation, plus a custom email/password auth system backed by DynamoDB.

## Architecture Overview

Authentication spans three layers:

1. **Infrastructure** (`infra/modules/backend/cognito.tf`) — Cognito User Pool, Client, Google IdP
2. **Backend** (`infra/modules/backend/src/app.py`) — Dual JWT verification (Cognito RS256 + Custom HS256)
3. **Frontend** (`src/pages/login/Login.js`, `src/utils/apiClient.js`) — Token parsing, session management

## Infrastructure (Terraform)

### Cognito User Pool

- Pool name: `amrit-portfolio-users-${var.environment}`
- Auto-verified attributes: `email`
- Username attributes: `email` (users sign in with email)
- Password policy: min 8 chars, requires lowercase, uppercase, numbers, symbols

### Cognito User Pool Client

- Name: `portfolio-frontend`
- `generate_secret = false` (required for SPAs / React apps)
- OAuth flows: `code` and `implicit`
- OAuth scopes: `email`, `openid`, `profile`
- Callback URLs: `https://amrit.cloud/login`, `http://localhost:3000/login`
- Logout URLs: `https://amrit.cloud/`, `http://localhost:3000/`
- Identity providers: `COGNITO`, `Google`

### Cognito Domain

- Pattern: `${var.project_name}-auth-v2-${var.environment}` (e.g., `my-portfolio-auth-v2-prod`)
- Full domain: `${domain}.auth.${region}.amazoncognito.com`

### Google IdP

- Provider type: `Google`
- Scopes: `email profile openid`
- Attribute mapping: `email → email`, `username → sub`, `name → name`, `picture → picture`
- Credentials come from `var.google_client_id` and `var.google_client_secret`

## Frontend Authentication

### Environment Variables

```
REACT_APP_COGNITO_DOMAIN=my-portfolio-auth-v2-prod.auth.us-east-1.amazoncognito.com
REACT_APP_COGNITO_CLIENT_ID=<client_id>
REACT_APP_COGNITO_USER_POOL_ID=<pool_id>
REACT_APP_CUSTOM_API_URL=<api_gateway_url>
```

### Social Login Flow (Google via Cognito Hosted UI)

1. User clicks "Sign in with Google" → redirects to Cognito Hosted UI
2. Cognito redirects back to `/login#id_token=<jwt>&...` (implicit flow)
3. `Login.js` `componentDidMount()` → `handleUrlParams()`:
   - Extracts `id_token` from URL hash fragment: `window.location.hash`
   - Parses JWT payload: `JSON.parse(atob(idToken.split('.')[1]))`
   - Constructs user object with fields: `username`, `name`, `picture`, `type: "cognito"`, `role`
   - Stores in sessionStorage via `setSession(idToken, user)`
   - Admin check: `payload.email === "amrit.bhattarai990@gmail.com"` → redirect to `/admin`
   - Regular users → redirect to `/home`

### Email/Password Login Flow

1. User fills email/password form → calls `loginAdmin(username, password)` from `apiClient.js`
2. `apiClient.js` POSTs to `${API_URL}/auth/login`
3. On success, stores JWT token and user info via `setSession(token, user)`

### Session Management (apiClient.js)

- Storage: `sessionStorage` (not localStorage — cleared on tab close)
- Keys: `admin_auth_token`, `admin_user_info`
- Functions:
  - `getStoredToken()` — retrieves JWT token
  - `getStoredUser()` — retrieves parsed user object
  - `setSession(token, user)` — stores both
  - `clearSession()` — removes both

### Mock Fallback Pattern

When `REACT_APP_CUSTOM_API_URL` is not set (local dev without backend):

- `loginAdmin()` accepts any password ≥6 chars and returns mock token
- `signupAdmin()` creates mock session immediately
- All auth functions fall back gracefully

## Backend Authentication

### Dual JWT Verification Strategy (`authenticate()` function in app.py)

The `authenticate()` function tries verification in this order:

1. **Custom HS256 JWT** — `verify_jwt(token)`:

   - Uses HMAC-SHA256 with `JWT_SECRET` env var
   - For tokens generated by the custom signup/login system
   - Checks expiration (`exp` claim)

2. **Cognito RS256 JWT** — `verify_cognito_jwt(token)`:
   - Fetches JWKS from `https://cognito-idp.{region}.amazonaws.com/{pool_id}/.well-known/jwks.json`
   - Uses `python-jose` library for RS256 verification
   - Options: `verify_aud: False`, `verify_at_hash: False`
   - Standardizes claims to match custom JWT format
   - Admin detection: checks if `email == ADMIN_EMAIL` env var
   - Returns `{'error': ...}` dict (not None) on verification failure

### Critical: Error vs None Handling

```python
payload = verify_jwt(token)        # Returns None if invalid
if not payload:
    payload = verify_cognito_jwt(token)  # Returns {'error': ...} or valid payload
    if payload and 'error' in payload:
        print(f"Authentication failed: {payload['error']}")
        return {'__auth_error': payload['error']}
return payload
```

- `verify_jwt()` returns `None` on failure → triggers Cognito fallback
- `verify_cognito_jwt()` returns `{'error': ...}` on failure → this is **truthy** in Python
- The `__auth_error` key propagates the error message to route handlers

### Lambda Environment Variables

```
COGNITO_USER_POOL_ID  — Pool ID for JWKS URL construction
COGNITO_REGION        — AWS region for JWKS URL
COGNITO_CLIENT_ID     — Client ID (used for validation)
ADMIN_EMAIL           — Email that gets admin role
JWT_SECRET            — Secret for custom HS256 tokens (fallback: ADMIN_PASSWORD)
```

## ⚠️ Known Gotchas and Past Bugs

### 1. COGNITO_CLIENT_ID Must Be Passed to Lambda (PR #49)

The Lambda function needs `COGNITO_CLIENT_ID` in its environment variables for JWT validation. This was missing and caused 401 errors for all Cognito-authenticated requests. Ensure `main.tf` includes:

```hcl
environment {
  variables = {
    COGNITO_CLIENT_ID = aws_cognito_user_pool_client.client.id
  }
}
```

### 2. Cognito JWT Error Bypass Bug (commit c38eb62)

When `verify_cognito_jwt()` returns `{'error': 'some message'}`, this is **truthy** in Python. Previously, code like `if not payload:` would pass error payloads through as valid authentication, allowing unauthenticated users to post comments. The fix: check for `'__auth_error'` key in the returned payload.

### 3. Google Sign-In NXDOMAIN Error (PR #48)

The Cognito domain must match exactly what's configured in Terraform. Mismatches between `REACT_APP_COGNITO_DOMAIN` and the actual Cognito domain cause DNS resolution failures during Google OAuth flow.

### 4. Callback URL Matching

Cognito strictly validates callback URLs. Both `https://amrit.cloud/login` AND `http://localhost:3000/login` must be in the `callback_urls` list in `cognito.tf`. Missing entries cause OAuth redirects to fail silently.

## Checklist: Adding Auth to a New Feature

- [ ] If the route needs authentication, call `authenticate(event)` in the handler
- [ ] Check for `__auth_error` key before checking `None`
- [ ] For admin-only routes, verify `payload.get('role') == 'admin'`
- [ ] On the frontend, use `getStoredToken()` to get the Bearer token
- [ ] Add mock fallback in `apiClient.js` when `API_URL` is not set
- [ ] Add tests in both `test_app.py` and `apiClient.test.js`
